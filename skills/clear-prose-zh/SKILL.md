# 清晰连贯的中文写作

让读者顺着文字理解事实和逻辑，无须自行补全关系。消除歧义和阅读阻力，不把自然行文改成指令清单。

优先级：**原意准确 → 逻辑清楚 → 行文连贯 → 措辞精练。**

短句、主动语态、列表都是可选手段，不是合规目标。只采用一套默认原则，不分严格档和宽松档。

## 适用边界

- 润色已有中文技术文本，或在事实与要求明确时起草说明文字。
- 用户要求表达自然、上下文连贯，或指出短句太碎、重复啰嗦、翻译腔重。
- 操作步骤仍可用编号列表，报错仍可简短；不要为追求连贯把本应独立的操作或警告合并。
- 不替代事实核查、技术设计或内容论证。原文缺少信息时，不能靠润色补造。
- 用户明确要求严格受控语言时，遵循其指定规范，不声称本技能提供这种合规保证。

## 不可牺牲的准确性

1. 保留事实、数字、单位、对象、条件、例外、范围、时间状态和否定关系。
2. 保留置信度与约束强度：“可能”不能变成确定，“建议”不能变成“必须”，“尚未验证”不能变成“验证失败”。
3. 保留逻辑方向：“只有 A 才 B”不能改成“只要 A 就 B”；现象同时出现不代表因果，也不代表先后顺序。
4. 不为了通顺添加原文没有的原因、机制、效果、执行顺序或承诺。可以显化已有逻辑，但不能凭常识补出新的逻辑。
5. 术语所指保持一致，但不要把不同概念强行合并。例如“检查”“校验”“确认”是否同义，要由具体语境决定。
6. 代码、命令、路径、标识符和接口字段默认原样保留；不要把可执行内容当作普通措辞润色。

如果存在会改变结论的歧义，先提出聚焦问题；如果不影响其他部分，可以改写明确部分并简要指出歧义。不要猜测作者意图后伪装成确定表述。

## 句子：按表达中心组织，不按字数拆分

一句围绕一个表达中心组织。一个中心可以包含条件与动作、原因与结果、对比，或同一目的下的连续动作。

- **该合并时合并。** 相邻短句主语相同、关系紧密，而且合并后条件作用范围清楚时，可以连成一句。
- **该拆分时拆分。** 主题或执行者切换、分支过多、条件作用范围不明，或者读者需要反复回看才能确定主干时，拆句或改用列表。
- **没有硬性句长限制。** 长句不自动等于难读，短句也不自动等于清楚。不要为了句长删除限定语，不要为了“自然”把所有短句合成长句。
- **保留有用连接。** “如果”“因此”“但”“完成后”等承载逻辑时应保留；“并且”“同时”“从而”不是禁词。只有在关系有依据时才添加连接词。
- **自然处理主语。** 主语明确且不变时可以省略；执行者变化或代词可能指向多个对象时，明确点名。避免每句重复同一个主体，也不要留下悬空指代。
- **按信息重点选择语态。** 主动语态有助于明确责任，但施事未知、无关或重点在受影响对象时，被动表达完全可用。
- **保留必要体貌。** “已完成”“正在执行”“曾经发生”表达不同状态，不机械删除“已”“正在”“过”等词。
- **标点服务层次。** 逗号、分号、冒号和破折号均可使用；不要只替换标点而不处理句内关系。

## 段落：让信息顺着读者的理解推进

每段围绕一个中心问题展开，句子之间要有可辨认的承接关系。按内容选择“结论—理由”“现象—解释”“条件—处理”等顺序，不要求每段套同一个模板。

- 先给读者理解后文所必需的信息，再引入新对象或新结论；不要突然切换话题。
- 如果重排句序能消除跳跃，可以重排，但不得改变时间顺序、条件归属或论证关系。
- 可以重复关键术语来维持话题，不必为了避免重复而轮换同义词；删除的是无助于理解的重复表述。
- 解释、原因和论证优先写成自然段；独立步骤、并列选项、检查项适合列表；真正需要逐项比较时再用表格。
- 不为每句话加标题，不将连贯论述切成大量单句段，也不按固定句数切段。
- 连接词不是越多越好。关系已经清楚时，可以直接承接，不必机械添加“首先、其次、此外、综上”。

## 措辞：消除阅读阻力，保留作者声音

优先使用具体、直接的表达。删去不承载信息的套话、重复修饰和空泛评价，例如把“对日志进行分析”改成“分析日志”。但不要按词表盲删：判断一个词在当前语境中是否表达了必要含义。

必要术语保留。只有原文或已提供材料包含定义时，才据此补充解释；不能自行编造定义。缺少测量值时，不把“很快”擅自改成“3 秒内”。

保持原文适合读者的语气与详略，不强行写成公文、口号或聊天腔。允许长短句交替，不为制造节奏而改动信息。精练是减少理解成本，不是减少字数。

## 工作流程

1. **先理解。** 确认读者、用途和不可丢失的信息。可从上下文判断的不要反复追问；关键歧义必须澄清。
2. **找阅读障碍。** 通读全文，定位逻辑跳跃、指代不清、过度拆句、过度嵌套和冗余，不把每句话预设为有问题。
3. **先组织，再措辞。** 必要时调整段落和句序，再决定合并或拆分，最后精简用词。只做解决问题所需的改动。
4. **对照保真。** 逐项核对事实、条件、范围、情态、否定、时间状态和逻辑方向，确认没有新增断言或遗漏例外。
5. **连贯性复读。** 把改稿当作一篇完整文字读一遍：是否需要脑补关系？是否反复点名同一主语？有没有突兀跳转、连接词堆叠或无必要的列表？按实际问题回改。
6. **及时停手。** 原文已经准确、清楚、自然时就保留，不为了体现改写效果而换词。好句子不必符合统一形状。

改写示例或需要判断“该不该合并”时，阅读 [前后对照与检查样例](examples/before-after.md)。示例不是模板，不要套用示例中原文未提供的逻辑关系。

## 输出约定

- 默认只输出可直接使用的正文，不加技能介绍、档位声明、规则计数或润色总结。
- 原文无需修改时，直接返回原文；用户要求评估时，再说明无需修改的理由。
- 用户要求前后对照、解释修改或检视意见时，再给对应内容，重点说明理解成本如何降低，而非“违反了几条规则”。
- 存在阻碍准确改写的歧义时，可以提问或附一条必要说明；不要用通顺的表述掩盖不确定性。
- 是否写入文件、改哪个文件，遵循用户授权；调用本技能本身不授权修改其他文档。

## 最终自检

- 信息是否完整，语气强度和条件作用范围是否不变？
- 每个新增连接词是否有依据，是否把并列写成了因果或顺序？
- 句子是否围绕清楚的表达中心，段落是否自然承接？
- 是否因机械拆句而割裂逻辑，或因合并而增加理解负担？
- 是否保留了必要术语、时间状态和作者原有的自然表达？
- 是否有仅为显得“改过了”而做的改动？有就撤回。
